# Current Architecture

This document describes implemented behavior for Release 1 (Local Adversarial Validation Core). The ADRs under `docs/adr/` describe accepted target architecture; their `implementation` metadata states how much is current guarantee.

## Entry points

`orca-no-mistakes` supports three commands:

- `run` launches the coordinator detached in an isolated child gate worktree and dedicated Orca terminal tab and returns `{"detached":true,"terminalHandle":"..."}`. If `--notify <handle>` is passed or `ORCA_TERMINAL_HANDLE` is set, the coordinator also notifies that terminal when a decision gate opens and notifies and wakes the originating session on terminal run outcomes (`passed`, `failed`, or `cancelled`). (The internal `--attached` flag runs synchronously inside the spawned terminal tab).
- `attestation export|verify` reads or checks Passed Attestation manifests against the domain ledger and retained evidence.
- `prune [--before <date>] [--repo <substring>]` deletes completed runs (cascading checkpoints, evidence, gate audit rows, attestations) plus their artifact directories.

The runner requires an explicit single-line `--intent`, a clean, committed, named feature branch, rejects the detected default branch, verifies an `origin` remote, and optionally checks an expected `--head` SHA. It fetches and rebases onto the selected base before validation continues.

## Domain ledger

All identity and provenance state lives in SQLite at `~/.orca-no-mistakes/ledger.db` (WAL mode, foreign keys on), created via `node:sqlite`. Tables:

- `runs` — one row per pipeline attempt with submission commit OID, base branch/OID, intent + intent hash, trusted-policy hash, and terminal status (`in-progress`, `passed`, `failed`, `cancelled`).
- `branch_leases` — one exclusive semantic lease per `(repo_root, branch)` with a monotonically increasing generation token and heartbeat timestamp. A second run on a leased branch fails closed; `--force-lease` reclaims it. The lease heartbeat is checked before every stage and each fix round; losing the lease aborts the run. The lease is released when the run passes or fails.
- `stage_checkpoints` — the intent stage records a reconciliation snapshot at round 0; every fixer round records its input and output commit OIDs (each fixer must commit a distinct change).
- `stage_evidence` — one row per stage execution binding stage id, round, candidate/base commit OIDs, worker identity, exit code, summary, artifact path, and the SHA-256 evidence digest.
- `gate_audit` — every human gate resolution with question, offered options, raw resolution, parsed decision, and guidance.
- `passed_attestations` — one row per passed run keyed by run ID, holding the manifest JSON and Merkle root; lookups by candidate commit OID return the most recent attestation.

Set `ORCA_NO_MISTAKES_HOME` to relocate `~/.orca-no-mistakes` (used by tests and sandboxes).

## Orchestration

The coordinator creates one Orca Run and an ordered six-task DAG:

`intent -> rebase -> review -> test -> document -> lint`

`intent` records the supplied objective behind `<untrusted_instruction>` framing. `rebase` is a coordinator-run Git operation; the other stages are worker evaluations returning structured reports. Release 1 executes no remote push, PR creation, or CI reconciliation.

Reviewers run as fresh workers in disposable child worktrees. A compatible fixer terminal and child worktree are retained across fix rounds, with each committed repair applied back to the coordinator's isolated gate worktree; changing the primary configured fixer, observing that its worktree no longer matches the pre-round head, finding uncommitted changes, or failing to acknowledge retained-worker completion releases it before launching a fresh session. Another round enters through Orca's supervised `worker-start --terminal` path, which verifies that a recognized agent process still owns the terminal before delivering the authenticated task; a terminal that returned to its shell is released and retried through the fresh configured chain even when its stale title still names the old harness. If a retained terminal fails before accepting another round, the coordinator releases it and retries the full configured chain in fresh child worktrees. Retained fixers are released before a human gate opens. Every successful fixer round must leave a clean worktree and create a new commit. A fixer that reports no applicable change is cleaned up, recorded as evidence, and routed to the human gate so the operator can approve or skip a false finding or explicitly retry it.

Fixer prompts restrict edits to implementation source and new regression tests (or the narrower stage-specific document/rebase scope). The coordinator binds policy inspection, custody transfer, and post-transfer HEAD verification to the same exact fixer commit OID, rejecting a worker or concurrent writer that substitutes a later commit after validation. Ordinary fixer commits must descend from the pre-round head; only a rebase fixer validated against its resolved upstream commit and reported conflict files may rewrite history. It rejects changes to tests present at the pre-round head, validation command/configuration files (including test-runner selection), its executable entrypoint, imported coordinator modules, or `scripts/orca-no-mistakes.ts` before applying a fixer commit. Documentation under `docs/prompts/` remains ordinary document-stage content. A rejected protected-path commit is cleaned up, recorded as stage evidence, and routed to an indefinite human gate with the complete structured stage report preserved rather than terminating the run.

This deliberately includes mechanical test/lint edits to an existing test file because the coordinator cannot prove that a file-level rewrite preserved its assertions. The path-level guard covers dedicated test files, including Perl `t/*.t`, Terraform `*.tftest.hcl`, Gherkin `features/*.feature`, Bats `*.bats`, `specs/` and `__specs__/` directories, prefix-style `testFoo` and `TestFoo` names, C++ `*_unittest` files, snapshot assertions under `__snapshots__/` or `*.snap`, fixture/golden data under conventional `testdata`, `fixtures`, `__fixtures__`, or `golden` directories, Cypress/Playwright-style `*.cy.*` and `*.e2e.*` files, and pytest `conftest.py`. For ordinary implementation paths, the coordinator compares committed blob contents directly, independent of Git attributes and textconv. A pre-round source file containing a recognizable assertion or direct/chained test registration anywhere in the source is immutable to fixers, covering control-flow-prefixed registrations, multiline continuations, and chained skip/only changes without language-specific parsing. Any changed pre-round path referenced by a protected manifest, CI workflow, or runner/build configuration is also protected; references resolve from both the repository root and the referring manifest's directory. A referenced local action protects its complete tracked implementation tree, while unreferenced files with similar names remain editable. Rebase fixers must produce linear history on the resolved upstream commit, match Git's deterministic merge result outside the reported conflict files, and limit manual resolution to those conflicts. Custody updates the operator worktree only while detached and moves its named branch through an exact compare-and-swap, preserving concurrent branch advances. A timeout before or during custody transfer restores the pre-round head; once transfer finishes within the deadline, coordinator verification and cleanup finish under their normal command bounds. Final certification remains fail-closed until the retained fixer terminal and worktree are released.

Validation references normalize optional trailing directory separators and resolve each CI step's `working-directory` or a shell command's `cd` together with that same command path, including newline-separated shell blocks, so separate steps cannot cross-match unrelated files with the same basename. Non-YAML policy sources such as Jenkinsfiles are inspected as complete shell blocks so directory context survives intervening setup commands. Referenced local actions protect nested action implementations throughout every enclosing action tree. A workflow `uses: ./` protects the root action manifest and the implementation paths that manifest references. Implicit Bazel and Gradle policy files such as `.bazelrc` and `gradle.properties`, plus Gradle and Maven wrapper scripts, properties, and implementation files, are protected without requiring textual references.

A successful fallback fixer remains compatible while the exact configured candidate chain and order stay unchanged. Common GitHub, Forgejo, GitLab, CircleCI, Jenkins, Azure Pipelines, Buildkite, Bitbucket, Travis, and AppVeyor CI configuration, complete local GitHub/Forgejo action implementation trees, CMake and Bazel build/test entrypoints, Maven and Gradle build policy including `.mvn/maven.config` and `settings.gradle(.kts)`, Go module/workspace manifests, PHPUnit runner configuration, TSLint configuration, dependency lockfiles, any `conftest.py`, and the imported coordinator modules (`scripts/adapters.ts`, `scripts/config.ts`, `scripts/ledger.ts`, and `scripts/policy.ts`) are protected validation policy and cannot be changed by a fixer commit.

Dedicated test-path protection also recognizes `.Tests` project directories, hyphenated `foo-test` and non-document `test-foo` names, and Pascal/camel-case `Test(s)` or `Spec(s)` filename suffixes. While a human gate is open, the coordinator inspects and acknowledges the complete Orca delivery, applying authenticated gate responses and warning about unrelated messages rather than blocking or discarding the batch silently.

Each stage and role resolves its own agent from the configuration tiers, and the launch adapter dispatches on the resolved harness:

- `cursor` launches through native `orca orchestration worker-start`, which receives the resolved model, effort, and timeout as flags. Fresh Claude, Codex, Antigravity, and Kimi workers create their authenticated dispatch first, then launch through a local terminal with a short instruction to read the mode-0600 preamble artifact. Kimi uses noninteractive `--prompt` mode without the incompatible `--auto` flag, and a brief startup-output grace period converts immediate argument, authentication, or terminal failures into preflight failures before normal mailbox waiting. Retained CLI sessions re-enter through supervised `worker-start --terminal`, which validates agent ownership and delivers the authenticated task. Codex reasoning effort maps to `model_reasoning_effort` and automation uses `--dangerously-bypass-approvals-and-sandbox`. This avoids native fresh-launch prompt stalls, empty initial TUIs, prompt-processing races, and OS argument-size limits.
- Fresh terminal workers wait 20 seconds when the controller's default shell is fish, allowing hidden panes to finish fish's ten-second terminal-query timeout and settle at a writable prompt before the startup command is sent. `WORKER_SHELL_STARTUP_DELAY_MS` overrides this compatibility delay. `opencode`, `grok`, and `gemini` then dispatch instructions by injection. `agy` receives its authenticated preamble through a protected prompt file passed to `--prompt-interactive`; because that carrier is a managed option, AGY overrides may not contain an option terminator. Its adapter also provides custom readiness matching and automatic workspace trust configuration in `~/.gemini/antigravity-cli/settings.json`. Trust updates serialize behind an owner-identified lock, reclaim only locks owned by a proven-dead process, and fail closed after a bounded wait when ownership cannot be resolved safely. Mandatory unattended flags are emitted before every `agent_args_override`, so an option terminator cannot turn them into positional text; overrides may add non-reserved arguments but may not supply managed permission, approval, sandbox, profile, or prompt controls, and resolved effort is passed through the harness-specific knob. Startup output naming the harness binary itself as missing fails immediately as `binary-missing` instead of burning the readiness timeout. Terminal titles remain the primary readiness signal; Codex additionally accepts its active working indicator plus model/effort footer because hidden Codex panes can retain the worktree title while already processing the task. Before each attempt, the coordinator removes the assigned report file. A successful worker may omit `--report-path` only when it wrote that newly assigned file; supplied paths must equal the assigned path and still pass canonical artifact containment checks. Worker reports and ACP stdout are parsed with closed JSON fences preferred over unclosed tails; disagreeing candidates fail closed at every layer, including the last-resort bare-object fallback.
- Every non-retained fixer outcome uses strict cleanup. If report validation, policy inspection, custody, or execution fails and the terminal/worktree cannot also be released, the cleanup failure is surfaced with the original fixer failure preserved as its cause; certification and fallback remain blocked.
- Retained `worker-start` receipts are parsed before fallback decisions. A receipt that exposes a dispatch but is not ready is abandoned before the retained session is released or another candidate starts.
- Antigravity lock reclamation preserves the ownerless lock's pre-claim identity and age, so creating the reaper claim cannot make the stale lock appear new.
- Co-located Zig `test "..."` declarations and `std.testing.expect*` assertions are protected. Playwright `*-snapshots` baselines are treated as test assertions. ShellCheck's implicit `.shellcheckrc` and Pipenv's `Pipfile` are protected validation policy.
- Rust test attributes include namespaced async/proc-macro forms such as `#[tokio::test]` and `#[rstest]`; JUnit `@ParameterizedTest` and NUnit `[TestCase]` registrations are protected too. Canonical Scala, Swift, Zig, Composer, Ruby, .NET, Elixir, and Dart package/build manifests and their standard lockfiles are protected validation policy because their test targets may be discovered implicitly.
- Qualified C# registrations and assertions, including NUnit and MSTest namespace-qualified attributes plus `Assert.*` calls, make a pre-round implementation source immutable to fixers.
- Recognizable JavaScript assertions include Chai modifier/property chains such as `value.should.not.equal(...)` and destructured Node assertion calls when the source imports `node:assert`, including `ok`, `equal`, `deepEqual`, `match`, and strict variants.
- Robot Framework `.robot` suites and `.resource` keyword files are dedicated test assets. Any pre-round source importing `node:assert` or `node:assert/strict` is immutable to fixers, so aliased assertion APIs cannot bypass protection.
- Nox's implicit `noxfile.py` runner configuration is protected validation policy.
- Central MSBuild policy files `Directory.Build.props`, `Directory.Build.targets`, and `Directory.Packages.props` are protected case-insensitively because projects import them implicitly.
- Jest image baselines under `__image_snapshots__/` are treated as test assertions alongside `__snapshots__/`, `*-snapshots`, and `*.snap` files.
- Executable sources under a singular `spec/` directory are protected while declarative specification artifacts such as `spec/openapi.yaml` remain editable.
- Validation references normalize environment/workflow-expression prefixes, optional trailing directory separators, and POSIX or Windows path separators before resolving the command target. Shell `cd` and `pushd` directory changes use the same normalization, including quoted `$ENV/...` and `${{ ... }}/...` paths. Local-action directory references may include a trailing separator.
- Shell-composed validation references track nested relative `cd`/`pushd` transitions and `popd`, retaining directory context through `&&`, `;`, newline-separated setup commands, and guarded `cd dir || exit ...; command` forms.
- Codex `-c model=...` and `-c model_reasoning_effort=...` pins take precedence over mapped values, normalize whitespace around `=`, and must contain nonempty values. Worker waits ignore stale messages from prior sequential dispatches instead of failing the active worker.
- Worker waits ignore syntactically malformed or non-object metadata that cannot be attributed to the active dispatch; a valid active completion later in the same delivery still wins, while a delivery with no valid active message is acknowledged and polling continues.
- Known harness names are normalized case-insensitively before launch classification, managed safety flags, effort mapping, override lookup, and prompt-mode selection. Unknown custom executable names retain their original casing.
- `acp:<target>` harnesses run through the `acpx` runner (`acpx --format quiet --approve-all <target> exec "<prompt>"`) and must return a JSON stage report.

Reviewer reports require canonical structured findings because they drive gates and fixer selection. Fixer reports use only their summary, tested commands, and declared artifacts; noncanonical fixer finding metadata is ignored because commit ancestry, protected-path policy, and exact-OID custody independently decide whether the repair may be applied.

Terminal-launched harnesses use per-harness readiness matchers; startup waits up to `WORKER_AGENT_READY_TIMEOUT_MS` milliseconds (default 60000) before the terminal and any allocated worktree are torn down. With no configuration the default remains one `opencode` worker per role on the agent's own default model; `--reviewer-model`, `--fixer-model`, and `--fixer-effort` override per role at the highest precedence.

## Validation policy

Two provenance rules bind every run. First, repository agent configuration is read from `.orca/no-mistakes.yaml` on the trusted base ref (`git show origin/<base>:.orca/no-mistakes.yaml`); an absent file resolves to an empty policy, and an unresolvable base ref fails the run. Second, the coordinator hashes its own script files as they exist at `origin/<base>` and records that digest in the ledger and attestation. Reviewer prompts frame repository content, diffs, and instructions as untrusted data; policy changes may only come from the coordinator prompt itself.

The extracted configuration supplies per-stage and per-role agent selection and is merged under the CLI flags. `--allow-local-config` reads the same path from the working tree instead, and `--config <path>` reads an explicit file that must exist. Either bypass marks the run uncertified: the Orca worktree status is prefixed `[uncertified: local config bypass]` and the artifacts manifest records `local_bypass`.

## Findings and gates

Findings are `auto-fix`, `ask-user`, or `no-op`. Reports containing only actionable `auto-fix` findings enter the fix loop automatically. The default maximum is three automated fix rounds, configurable via `--max-fix-rounds`. When the fix-round limit is reached with actionable findings remaining, the coordinator opens an exhaustion decision gate.

An `ask-user` finding or fix exhaustion opens an Orca decision gate offering `approve`, `fix [ids][: guidance]`, `skip`, and `stop`. Unknown resolutions fail closed. Gate-response deliveries are processed completely before their batch acknowledgement, so multiple decisions delivered together are not discarded; acknowledgement failure aborts rather than replaying already-applied decisions. `approve` and `skip` complete the stage with unresolved findings and are recorded in `gate_audit` and bound into the attestation as a waiver on that stage's final evidence entry. The adversarial review stage audits the diff for removed or weakened test assertions and relaxed linter/formatter/static-analysis rules, reconciling each against the declared intent. Relaxations the intent explicitly justifies are reported as informational `no-op` findings; anything else surfaces as a blocking `ask-user` finding with `id: unexplained-policy-relaxation` (`severity: error`) and opens a gate.

Human decision gates have no coordinator-imposed deadline, and the pipeline has no total-run timeout. Explicit role timeouts bound individual worker attempts only; when one expires, the active worker operation is the single cleanup owner that aborts its in-flight run-mailbox wait, shell startup delay, readiness polling, or ACP subprocess, closes terminals, removes child worktrees, and waits for the entire owning operation, including recovery anchoring and strict cleanup, before finalizing the failed attempt. Receipt-producing terminal/worktree creation, authenticated dispatch, and native or supervised `worker-start` are allowed to settle so the coordinator can parse their receipts and remove resources created at the deadline instead of orphaning them. A timed-out worker receipt with no terminal still requires strict dispatch abandonment and removal of every known worktree before the attempt settles. Fresh candidates do not advance to a fallback unless worker abandonment, terminal closure, and owned-worktree removal all succeed. ACP attempts check the timeout fence before and after worktree setup so an expired attempt cannot launch paid agent work afterward. Unconfigured runs remain available overnight or through multi-hour review/fix loops.

## Evidence

Worker JSON reports, coordinator stage logs, and declared artifacts are confined to `~/.orca-no-mistakes/artifacts/<run-id>/`. The coordinator validates report shape and prevents report or artifact paths from escaping that directory. Coordinator-written logs larger than 50 MB are capped to head + tail with an explicit truncation marker.

Each stage execution produces a `stage_evidence` row whose SHA-256 digest covers stage, round, candidate commit OID, base commit OID, worker identity, exit code, and summary. Each run also writes `manifest.json` beside its reports, recording `base_ref`, `base_ref_sha`, `local_bypass`, the effective policy configuration snapshot with resolved CLI overrides, and its `effective_policy_hash` (SHA-256 over key-sorted canonical JSON).

## Custody return

On success the coordinator evaluates the three-way containment proof between the submitted head (`C_sub`), the operator's branch head (`C_op`), and the terminal validated commit (`C_term`). It always anchors `refs/no-mistakes/recover/<run-id>` in the delivery repository at `C_term` first, before any head-advancing operation, so the gate worktree can be removed without stranding commits. When the pipeline ran directly in the operator's checkout, `C_op` is already `C_term` and no transfer is needed. In gate mode, a clean operator checkout still at `C_sub` is fast-forwarded to `C_term` by replaying the gate's commits. Every other case — divergent history, uncommitted operator changes, or a transfer that fails on the pipeline side — leaves the branch untouched; the recovery ref preserves the validated commits and the custody note names the ref plus the `git log` / `git rebase` commands to integrate it. Failed and cancelled runs likewise anchor their terminal gate head before teardown. Evidence is retained until explicit `prune`.

## Outcome

An attached run prints `{"runId":...,"steps":[...],"attestation":{...}}` after completion; the attestation manifest carries the run ID, candidate/base commit OIDs, trusted-policy hash, intent + intent hash, ordered stage-evidence entries (including waivers), Merkle root, and coordinator version. On failure the coordinator anchors the terminal gate head, appends the same recovery instructions to the terminal summary whenever the operator head differs from that anchored commit, throws, marks the run `failed` (or `cancelled` for a `stop` resolution), releases the lease, sets a nonzero exit status, and attempts to mark the worktree in review. If recovery anchoring fails, the gate and lease are retained instead of deleting the only reachable copy. Worktree-status update failures are logged as warnings rather than changing the pipeline result.

Not yet implemented from the target architecture: remote push/PR/CI stages, crash resumption of interrupted runs, canonical signatures over manifests, forge-side delivery verification, and guarded merge transitions. See ADRs 0003, 0004, 0006, 0007, and 0010.

Most subprocess commands time out after 120 seconds; worker orchestration uses longer waits. Gate polling inside the detached coordinator waits for human resolution or pipeline completion, while CLI commands return immediately to prevent agent deadlocks. `ORCA_CLI_COMMAND` overrides the Orca executable; the default is `orca` on macOS and `orca-ide` on Linux.
